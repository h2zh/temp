## 0. 一句话与产品体验

**一句话**：我们没有 GPU 预算做照片级渲染，游客照片又少又偏，照片级模型本来就很难看稳。所以改做**卡通"玩具"模型**：楼的**形状**来自公开的事实数据（OpenStreetMap 的建筑分件和高度），照片只用来把模型放准，并在配准通过时核验或修正尺寸。整栋楼都是**素模**（没有贴图、浅冷灰色、带淡斜纹的体块），画风可以整套替换（D7，`docs/ART_DIRECTION.md`）。

D29 之前，拍到的墙按照片上色，没拍到的墙挂"待解锁"牌子，拍照片就是"解锁"。D29 起模型不上色，也没有解锁的玩法。

### 0.1 用户看到什么

| 时刻 | 用户看到的 | 背后发生的事 |
|---|---|---|
| 地标有 OSM 分件快照 | 一座能认出轮廓的素模：塔、穹顶、尖顶都在 | OSM 分件（`building:part`）变成参数化积木（§3.1、STRUCTURE_FIRST §2.4），不需要任何照片 |
| 发布了一个点云模型 | 几秒到几十秒后，地标页这个模型旁边出现链接"风格化模型 · 素模（照片未对齐）"或"风格化模型 · 素模（照片已对齐）"；生成中显示"风格化生成中" | 风格化作业（§1.3） |
| 照片的配准被接受 | 仍是素模；照片证据可能改了形状：D15 自动采用的高度、D24 量出的立面凹凸、D25 的纠正，每处都能撤销 | §3.2、STRUCTURE_FIRST §2.4 |
| 配准被拒（今天每个真实众包模型都这样） | OSM 分件的素模；D15 撤回、不建 D24，D25 按配准等级保留 | §3.2 |
| 点任意一块积木 | 来源卡片，例如"形状：OpenStreetMap 志愿者测绘"、"照片量出（自动采用）"、立面凹凸的证据 | 每个面都带来源（provenance，§3.9） |

**这个转向的好处**（数字见第 6 节）：

1. **便宜**：核心路径不用 GPU；每次浏览的下载约 0.2–0.3 MB。
2. **对稀疏照片更友好**：没有照片也有一个认得出的素模；照片多了、配准过了，才用它们核验和修正形状。
3. **诚实看得见**：每个面都记着形状来自哪里，没有事实也没有测量的东西不画（§3.9）。

**代价**（直说）：模型不是"真实记录"，只有形状。颜色、材质、门窗图案都不显示（D29）；靠颜色才认得出的地标（洗礼堂的黑白条纹，STRUCTURE_FIRST §0.4）只剩形状。曲面壳体（悉尼歌剧院）用拉伸体块表示不了。

### 1.3 风格化作业什么时候跑

- **设计**：
  - 地标创建时导入 OSM 快照，生成体块登记表，直接发布一个全素模的 GLB（冷启动，§3.1）。
  - 每次有立面模型或完整模型通过 QA 门 1 并发布后，排一个 `stylize` 作业，产出一个新的风格化版本，走 QA（§3.9），通过才原子切换发布指针。优先级排在"首个立面"之后、"立面重建"之前；耗时几秒到两分钟，不需要单独的去抖。
  - 照片被撤回时，用到这张照片的风格化版本也标 `contains_deleted`，按 ARCHITECTURE §3.8 的 30 天规则重算。
  - D29 前的设计还有"按墙合并多个模型、已解锁的墙数不减"，是为上色设计的，随上色一起作废。
- **原型现在的做法**（比设计简单）：按模型做，不按地标合并。地标绑定了 OSM 分件快照时，每个发布的 COLMAP 模型排一个 `stylize` 作业（`crowd3d/jobs.py`，`Settings.stylize_published`）；重建作业优先，没有重建作业排队时才在子进程里跑 `crowd3d.structure_pipeline`（1200 s 上限、2 线程）。GLB 放在 PLY 旁边，由 `/files/models` 提供；`ModelInfo.stylized` 给出地址、配准结论和标签："素模（照片已对齐）"，或者配准被拒时的"素模（照片未对齐）"（D29 前前者叫"风格化（照片已对齐）"）。地标页在每个模型旁边链到 `stylized.html`。核心五栋 20 个最新发布的模型都出了 GLB，配准都被拒；每个子进程 CPU 中位 4.9 s、最多 19.7 s（STRUCTURE_FIRST §2.9）。目标显示了更新的模型时作业以说明结束；以前发布的模型要等重新发布才有 GLB。

## 2. 技术选型

### 2.1 选型总表

### 2.3 生成式模型：允许、有条件、禁止

**用户的规则**：生成式模型不得给没拍到的地方编造内容（不得编造看不见的立面和背面，不做图生 3D 补全，不修补未观测区域），但可以用来做简化和风格化。

**本文的执行方式**：规则管的是**结果**，不管用的是什么方法。所以下面这些规则对非生成式方法同样适用（例如把八角形一面的结构复制到对面，不用任何模型也是捏造）。D29 以后模型没有贴图，规则落在形状和数字上：每个形状和数字要么来自事实（OSM、约定），要么是照片量出来、带证据记录的（D15、D24、D25），要么是明确标出的占位（"高度待定"矮台，D13）。

**定义**：**观测掩码 M**：一面墙上满足 §3.3 全部条件、算"拍到了"的纹素。

| 类别 | 内容 | 护栏 |
|---|---|---|
| **默认（不用任何生成式模型）** | OSM 积木 → 经典方法的照片证据（天空掩码 A+R、SfM 点、三维线段）→ 判定规则 → 素模 GLB | §3.9 的检查 |
| **有条件允许** | ① 人、车、树、天空的分割，结果**只能用来从 M 里剔除像素**（代码里标 `GENERATIVE-OK` 的地方，例如 `clutter_mask()`）。v0 不用分割模型：人和车靠多视角一致和 SfM 点遮挡（§3.3）去掉，天空和植被靠 CPU 颜色、纹理规则。要加模型时，候选必须先过许可证（SegFormer、ADE20K 训练的权重、Ultralytics 的 AGPL 模型都不行）【待核实】；② 用点云拟合屋顶类型、简化形状（本身不是生成）；③ VLM 生成名称和导览文字，只进 UI，标"AI 生成说明"，不回流几何 | 模型输出只是"提议"；每次调用记录模型 id、版本、权重许可（谱系） |

## 3. 风格化算法

### 3.1 体块：形状来自事实

→ 结构优先：本节的实现部分（分件解析和过滤、屋顶原语和退化链、约定值 D17、空隙补体、冲突策略 D15）由 `docs/STRUCTURE_FIRST.md` §2.4 取代；参数化积木在 `crowd3d/structure.py`，判定规则在 `crowd3d/judge.py`。**D15 已拍板（产品负责人，2026-10-23）：至少两路照片证据一致就自动采用**（`judge.AUTO_ADOPT = True`，规则在 `judge.adoption_rule()` / `decide_frame()`，整个流程在 `judge.judge_landmark()`）。"一致"指：有争议的积木上 ≥ 2 路证据（天空轮廓线、SfM 点、三维线段）各自有 ≥ 3 张照片、各自给出数值（SfM 点永远不给"比地图低"的数，天空轮廓线给"比地图低"的数要上方是天空的照片 ≥ 3 张）；所有给出数值的路两两相差 ≤ max(1 m, 5%)，都在地图值的同一侧（有一路在另一侧或反向投票就是"矛盾"，只开工单）；都不撞拟合边界（天空剖面的上下界、三维线段搜索窗的边，`search_m` / `at_bound`），天空剖面满足核验的精度条件（两种掩码 ≤ 1.5 m、区间 ≤ 1.5 m、两种代价差 ≤ 1 格、不是平的）；不是细高构件；坐标工单已结（逐边残差门不过、或任何一路的整栋相似变换偏离 > 3% / 平移 > 1.5 m，都算坐标工单未结：`judge.frame_in_question()`，判定和开工单用同一条）；父件的改动已被接受。整体尺度没有确立时（`judge.scale_status()`：吸附尺度修正 > 3%，或者没有任何一路在四周墙面上量到 k 在 1 ± 3% 以内的整栋相似变换——吸附返回 ×1.00 本身不说明尺度对，单侧照片时它分不开尺度和平移），还要至少两路在尺度无关量上一致：各路量到的积木顶高 ÷ 同一路量到的主体（最大的落地分件）檐口高，相差 ≤ 5%，采用值 = 比值均值 × 地图上的主体檐口高（SfM 点量不到檐口，不能为尺度作保；主体本身是参照，这时不自动采用）。几路数值一致也挡不住的情况另有三条：有争议是"偏高"时，SfM 点（每点 ≥ 3 张照片）四周都到了地图顶高（容差内）而没有更高，说明墙面就停在地图高度，算一路反对（脚手架、树、后面的楼能让轮廓线和线段一起错）；三维线段的墙顶一簇如果高出这面墙自己的表面（墙带里 SfM 点最密的那个面）的点超过檐口容差，那一簇不是这面墙的顶（脚手架、前面的东西），这条边不出数；某一路把檐口量在地图檐口上（≤ max(1 m, 5%)）而顶高变了，说明变的是屋顶：改 `roof_height`、檐口不动（`judge.eave_rule()`），几路檐口说法不一就只开工单。父件先判定：父件被采用后，压在它上面的分件跟着移动（底和顶都移同样的量，自身高度不变，D16 ②），再在父件的新值上重新判定。坐标门（整栋楼的轮廓缩放和平移）按同一条规则自动采用：SfM 墙面平面和三维墙面线段各自求一个相似变换（`frame_similarity()` / `frame_similarity_lines()`），宽度和平移都相差 ≤ max(1 m, 5%)、同向、不撞边界，并且在采用后的轮廓上逐边残差门要通过；缩放偏离 > 3% 时还要过尺度无关核对（`judge.frame_scale_check()`）：在试采用的轮廓上，天空轮廓线和三维线段两路量到的主体檐口高都和地图檐口相差 ≤ max(1 m, 5%)（重建尺度就是地图的尺度），并且"轮廓宽 ÷ 檐口高"相对地图仍同向偏离 > 3%；否则开坐标工单（洗礼堂：檐口 18.6–18.8 m 对地图 18 m，通过）。限制：整体尺度误差小于这个容差加上地图檐口自身的误差时分不出来（例如重建 ×0.95、地图檐口又偏低 4%）。坐标门的两路证据不独立：三维线段只保留有 SfM 点支持的，所以墙面位置大体是同一批点再量一遍；设计 §2.2 里更独立的第二种方法（天空轮廓线在 (k, t) 上的网格搜索）还没有实现。采用的值来源记 `photo-fitted (auto)`，原地图值（`map_value`）和全部证据存进"可撤销"清单（`StructureModel.adoptions`，进 summary 的 `structure.adoptions` 和 GLB 的 `extras.structure.adoptions`；`judge.revert_adoption()` 撤销一条及依赖它的全部采用），查看器显示"照片量出（自动采用）"和地图原值（轮廓被采用时，每个节点的 extras 带 `outline_adopted`：采用编号、缩放、平移和地图原轮廓宽，查看器的形状一行注明"轮廓按照片整体缩放、平移"）；从不改写 OpenStreetMap。只有一路证据、或几路互相矛盾，照旧只开工单。"高度待定"矮台（D13）也可以这样得到照片量出的高度；没被采用时它永远是素模、状态永远是 `stub`（压在被采用的分件上时跟着移动，底高记"随下面的分件一起移动"，占位的顶高仍是 `default-style`、状态仍是 `stub`）；底面一半以上悬空的抬高分件（G10）开工单，碰得到支撑的留在地图位置，什么都碰不到的不画（`resolve_support()`）。地图值越过合理范围（分件顶 > 1000 m、> Wikidata 总高 × 1.1、> 其余分件最高顶 × 2.5）、数字标签解析不了、约定屋顶（没有 `roof:height`）占分件高度 70% 以上，都只开工单、不改值（`open_value_tickets()`）。采用的值会重画成实体（不会出现"已拟合"却画在地图值上的分件）。三维线段是第三路证据（`crowd3d/lines3d.py`，只当证据，永不变成几何）：它直接量高度，所以能投"偏高"也能投"偏低"；每条记录带区间、照片数和吸附尺度，吸附尺度修正 > 3% 时它不能单独决定（只在另一路强证据同向时才算一票）；少于 3 张照片不出数，没被线段覆盖的边列为"没拍到"、不出数；墙面自己的 SfM 点高过最高一簇水平线时那条边不出数（那是线脚，不是墙顶）。"照片核验"现在要两路证据一致：天空轮廓线（两种掩码）和三维线段量同一个量（檐口对檐口、顶点/屋脊对屋顶），彼此相差 ≤ max(1 m, 5%)，线段离地图值 ≤ 容差；发布门 `check_decisions()` 从记录里重算一遍。工单里带各路量到的值（SfM 点一路记成"地图顶高 + 点云比模型同区表面高出的量"，和顶高可比）、哪几路一致和 D15 的结论；被自动采用的积木，工单关闭并记下是哪一条采用解决的（撤销后重开）。发布门 `check_decisions()` 不相信写记录的代码：每个 `photo-fitted (auto)` 参数都从它自己的采用记录重算一遍 D15（`check_adoption_record()` / `check_frame_record()`），跟着父件移动的参数要和父件的采用对得上。

**裁决（体块来源）**：初始方向是"OSM 轮廓拉伸 + 用点云定高度"。三份草案和原型报告一致建议改为**优先用 OSM Simple 3D Buildings（S3DB）的分件**，点云只做核验。理由：

- **可用率很高**【本文复核产品草案的 OSM 快照】：评测目录 13 个地标全部有 `building:part`。按"分件中心落在主轮廓内（外扩 2 m）"过滤掉相邻建筑的分件后，每个地标有 4–132 个分件；12/13 的分件带 `height`（唯一例外是悉尼歌剧院，13 个分件都没有高度）；12/13 至少有一个分件带 `roof:shape`（例外是比萨斜塔：塔本身 29 个分件都没有；不过滤时唯一带 `roof:shape` 的 w265815356 离塔中心 42 m，是邻楼）。主轮廓本身带 `height` 的只有 4/13【几何】。
- **形状对**：分件带 `min_height`、`roof:shape`、`roof:height`，能直接搭出塔、穹顶、尖顶和门洞。亚琛的分件素模（西塔加尖顶、八角堂加穹顶、唱诗堂、小礼拜堂）一眼能认出来；原型从点云高度场切出来的体块是一团乱块，八角堂和哥特唱诗堂并成了一个 573 m² 的平顶块【原型 v1】【几何】，修复轮之后仍是一堆棱柱（D29 前的截图说明在 git 历史里）。
- **照片少时也稳**：洗礼堂只用 15 张真实照片时，屋顶没被拍到，模型退化成平顶八角"蛋糕"；OSM 写着金字塔顶（`roof:height=12`）加采光亭【产品】。
- 这些是人工测绘的事实数据，不是生成。用户的规则管的是"编造"，不是"引用事实"。

**来源优先级**：

| 优先级 | 来源 | 给出什么 | 来源标注 |
|---|---|---|---|
| 1 | OSM `building:part`（S3DB） | 分件轮廓、`height`、`min_height`、`roof:shape`、`roof:height` | `osm-s3db` |
| 2 | OSM 主轮廓 `height` / `building:levels`（× 3 m） | 单一高度 | `osm-height` |
| 3 | 点云：每条边墙带点 z 的 0.97 分位，再取各边中位数 | 檐口高度、屋顶形状核验 | `sfm-points` |
| 4 | Wikidata P2048 | **只作上界和核验，永远不直接当拉伸高度** | — |
| 5 | 风格默认值，同时开馆员工单 | 兜底；只用于有 OSM 轮廓、但没有任何高度事实也没有点云的体块（例如悉尼歌剧院的 13 个分件）。原文是 15 m 平顶，这也是编出来的尺寸，本文建议改成 3 m 高、顶边画虚线的"高度待定"矮台，由 §9 决定 D13 定。没有轮廓时不用（见下文"OSM 缺失时"） | `default-style` |

为什么 Wikidata 只作上界【几何】：P2048 是总高，含尖顶和穹顶。德累斯顿圣母教堂 P2048 = 91.24 m，而 OSM 主轮廓 40.65 m。拿总高拉伸整个轮廓，等于凭空造出一个 91 m 高的盒子。**导入时要按 rank 读**：圣家堂有 3 个值，但 172.5 m 是 preferred，138 m 和 162.91 m 是 deprecated（不同建造阶段的历史值）【本文核对条目】，导入器只取 preferred（没有 preferred 时取 normal 里最新的），并统一单位（双子塔的值是 1483 英尺）。

**做法**：

1. **取数**：建地标时按轮廓外扩 20 m 的范围取 OSM 快照（生产用 Overpass 或 Geofabrik 区域快照；本容器里 Overpass 连不上，草案用的是 OSM API v0.6 `/map`）。**要按包含关系过滤**：查询框会混进相邻建筑的分件。产品草案的查询框是轮廓外接尺寸的一半加 20 m，不过滤时各地标查出 4–134 个分件，按"分件中心在主轮廓内（外扩 2 m）"过滤后是 4–132 个；混进来最多的是勃兰登堡门（88 → 29）和圣家堂（70 → 26）【本文复核】。快照的 OSM 版本号和时间戳冻结进登记表。
2. **分件棱柱**：每个分件是一个从 `min_height` 到 `height − roof:height` 的棱柱，再加屋顶（S3DB 规定 `height` 量到屋顶顶部）。有分件时**不再渲染外轮廓体**（S3DB 惯例）。
3. **屋顶**（`roof:shape`）：按下表建，做不出来就按表里的顺序退，**不退成金字塔**（四坡顶、折线顶的屋脊退成尖顶，事实骨架就错了：匈牙利议会大厦有 56 个 hipped、10 个 mansard 分件）。每次退化都把原值写进来源记录（`roof.fallback_from`）。13 个地标过滤后的取值统计：flat 86、hipped 57、pyramidal 51、gabled 45、dome 10、mansard 10、round 5、onion 4、circular 3、spherical 3【本文复核】。

   | `roof:shape` | 做法 | 做不出来时 |
   |---|---|---|
   | flat | 平顶 | — |
   | pyramidal | 扇形三角面汇到质心 | flat |
   | gabled | 沿最小外接矩形长轴做屋脊 | 矩形度 ≤ 0.85：flat + 馆员工单 |
   | hipped、half-hipped、side_hipped | 四坡顶（直骨架，矩形可用最小外接矩形近似） | gabled，再不行 flat |
   | mansard、gambrel | 两段折线剖面 | hipped / gabled，再不行 flat |
   | skillion | 单坡，坡向按 `roof:direction`，没有就按长边 | flat |
   | dome、onion | 旋转体（6 环缩放） | flat |
   | cone | 圆锥 | pyramidal |
   | **round** | **沿长轴拉伸的半圆剖面（筒形拱顶）**，不是穹顶：OSM wiki 的定义是"横截面像半个圆，也叫 barrel roof"。原文按穹顶建是错的（圣母教堂有 1 个、悉尼歌剧院有 4 个 round 分件） | gabled，再不行 flat |
   | saltbox、crosspitched、sawtooth、butterfly、hipped-and-gabled、bellcast_gable、gabled_height_moved | v0 不实现 | gabled，再不行 flat |
   | many、circular、spherical、其他非标准值、缺失 | flat + 馆员工单；`roof:height` 只作核验 | — |
4. **简化**：轮廓用 Douglas-Peucker，容差逐步放大到 ≤ 32 个顶点且 Hausdorff ≤ 直径的 3%；接近正交的边吸附到主轴；正八边形这类真多边形保留（原型已实现：洗礼堂 13 → 10 个顶点，偏差 0.02 m；亚琛 200 → 30，偏差 1.92 m【原型】）。
5. **圆角**：转角倒圆，半径 = clamp(1.5% × 直径, 0.3 m, 1.2 m)，3 段（原型参数）。
6. **重叠分件**：分件交叠处会有共面闪烁的细线，要在体块阶段做布尔并，或给共面面做微小偏移【几何】。

**冲突策略**【几何，阈值为估算】：

- 只有 `georeg_level = full` 的模型能产生高度证据。原因：洗礼堂 NE 立面模型只有 6 张 GPS 照片（`prior_only`），它测出的檐口是 26.98 m，比实际高约 45%；其余模型在 17.9–19.0 m，OSM 是 18.0 m【几何】。
- 证据和 OSM 相差 ≤ max(2 m, 10%)：只记"已核验"，**不改值**。
- 冲突较大时，**不自动覆盖 OSM**：保留 OSM 的值，标"有争议"，开馆员工单。满足"完整模型、该件暴露区 ≥ 500 个点、bootstrap 区间（重采样估出的置信区间）宽 < 1 m、连续两个版本一致"的证据会排到工单前面，但改值要馆员批准，批准后来源记 `curator`（证据附在记录里）。理由：点云估计器本身可能有偏差，亚琛 14 个分件里 9 个比 OSM 高 7–16 m，谁对谁错还判不了（§9.3 第 2 条），这些分件大多能满足上面的点数和区间条件，自动覆盖会用一个有偏的估计替换可能正确的事实。
- **永不自动回馈 OSM**。馆员确认后的修正也只有在来源许可证允许向 ODbL 贡献时才回馈（§9 决定 D5）。
- **滞后**：已发布的体块，高度只有变化 > 2 m 且证据更强时才更新，避免版本之间模型来回跳（原型在 E 立面模型上算出 15.48 m 平顶、在完整模型上算出 18.71 m 金字塔顶，两版体块来回跳【几何】）。
- 细高结构信 OSM：亚琛西塔尖顶点云 q98 = 69.6 m，OSM 74 m，细尖顶点太少【几何】。

**OSM 缺失时不用点云闭合体块**。洗礼堂完整模型实测，点云凹包和 OSM 的 IoU 只有 0.22–0.57、Hausdorff 22.7 m：西侧没人拍，凹包就把背面"猜"成了别的形状【几何】。做法：

1. 名胜地标的 OSM 覆盖率很高（13/13）；建地标时把 OSM 轮廓列为必填，缺了由馆员手绘（约 2 分钟【估算】），来源记 `curator`。
2. 馆员画好之前，自动兜底**只显示已观测墙段**（来自平面拟合）加地面上一圈扁平的点云足迹线，**不画闭合体块**。半透明的"推断闭合体"和 15 m 的默认高度一样，都是给没人拍过、OSM 也没描述的部分编出来的几何，和点云凹包是同一类问题，只是轻一些，所以默认不做；要不要做由您决定（§9 决定 D13）。
   - 原型目前的做法（修复轮新增）是：没有可用轮廓时从点云描出轮廓、按普通体块拉伸，来源记 `sfm-points`。这比本条宽松，进生产前要按本条改。

### 3.2 吸附与坐标

→ 结构优先：加逐边残差门 G11（墙内侧 10 m 以内的点都算；不过就开坐标工单，那条边上的墙不算拍到、不用照片证据，发布时在 `structure_gates()` 里跑；只量配准通过的点，配准不过时整栋都不用照片证据，门不跑）；正多边形轮廓用整栋楼相似变换取代逐墙移动（`judge.frame_similarity()` 和三维线段的 `judge.frame_similarity_lines()`；两路一致时按 D15 自动采用，见 §3.1 的"结构优先"一段，否则开坐标工单交馆员；坐标工单里附"尺度假设"：照片点云高度 / 地图高度的中位数放在缩放 k 旁边，有 Wikidata 总高时也放上，因为 k 本身分不清是 OSM 轮廓画错还是重建尺度偏了）；第 4 条"尺度已修正"规则见 `docs/STRUCTURE_FIRST.md` §2.2、§2.4.2。

**坐标**：沿用地标 ENU（x 东、y 北、z 上，米）。GLB 用 glTF 的 y 朝上：ENU (x, y, z) → glTF (x, z, −y)，和 `web/viewer.js` 一致。地面取 z = 0（相机高度约定 1.6 m）；点云墙脚的低分位被人群和围栏挡住，不能用来定地面【几何】。

**吸附**：

1. **旋转只在配准偏航窗口内搜索**。窗口 = ±min(3σ_θ, P/2 − 5°)：σ_θ 是这个模型配准时报出的偏航不确定度（`reconstruct` 已经在日志里报，例如真实立面作业的"yaw ±4–6 deg"；模型 JSON 有地理锚点时取锚点的偏航 σ，`crowd3d/anchor.py`），P 是轮廓的旋转对称周期（正八边形 45°，矩形 180°，不对称取 360°）。窗口内多起点；最优解离窗口边 < 1° 就不吸附、打标记。
   - 为什么不用 ARCHITECTURE §3.5.7 的固定 ±10°：洗礼堂参考模型成功的吸附要转 −9.42°，已经用掉窗口的 94%【原型】；ARCHITECTURE §3.5.3 算出单个立面只靠 GPS 时 σ_θ ≈ 13°。固定 ±10° 会把很多正常的真实立面当成"落在窗口边上"拒掉。
   - 为什么一定要窗口【几何】：原型的全局 ICP 在洗礼堂完整模型上收敛到 −90.58° 的对称别名解，墙面中位距离 0.402 m，**比正确解附近的 0.44–0.48 m 还小**。护栏拒掉了这个解，模型因此偏 3.9 m 没吸附，南墙贴上了乔托钟楼的图像（D29 前，墙还按照片上色）。真实链路上也一样：3 个 6–7 张照片的立面作业，不加约束的 ICP 分别收敛到 92.5°、78.9°、88.7°【本文】。窗口不超过 P/2 只在真实误差落在窗口内时才挡得住别名：报出的 σ_θ 大或者没有时，3σ_θ 超过 P/2 − 5°，窗口被截短，一个周期之外的别名就在 3σ 之内，对抗用例里转错 44–180° 的解过了门（任务 #73，69 个错误通过）。所以现在【原型】：窗口被对称周期截短、或者模型没报偏航 σ 时，吸附直接拒绝；吸附后相机到自己 EXIF GPS 的中位距离超过 max(20 m, 3 × 地理锚点在相机处的水平 σ) 也拒绝（`StyleParams` 的 `snap_refuse_clipped_window`、`snap_max_gps_median_m`、`snap_use_anchor`）。对抗用例 69 个错误通过降到 0；没有配准先验的场景（GT 定位的参考模型、测试）照旧用默认窗口。
   - **近似旋转对称的轮廓**（圆形的比萨斜塔、16 边形等，P/2 − 5° 小于 3σ_θ 时）：偏航从轮廓上看不出来，只搜平移，偏航沿用配准结果。
2. **平移搜索 ±25 m，接受靠逐边核验，不靠"修正量小"**。单张照片的真实 GPS 误差 p90 在洗礼堂是 20.3 m、亚琛 55.0 m（REAL_WORLD_EVAL，对轮廓校正后的参考），模型配准把多张照片平均后小一些：真实立面模型相对轮廓校正参考的水平误差中位数 4.7–10.4 m【产品】，12 台相机的那个作业偏 17.8 m，所以 ARCHITECTURE §3.5.7 的 8 m 上限太紧（§8 已列）。接受条件（原型 `registration_check`）：吸附后，点数达到中位边 25% 的轮廓边每条一票，≥ 60% 的边中位距离 < 3 m，而且通过的边方向至少相差 30°（全平行时沿墙方向的平移看不出来）。
   - 只拍到一面墙的立面模型（例如矩形建筑的一面），沿墙方向的平移看不出来，核验过不了，就不用照片证据。宁可不用，也不把照片证据放歪 10 m。
   - 已实现（2026-10-23 第二轮，`stylize.snap_to_footprint`，替换了"不加约束的 ICP + 拒绝超过 20° / 20 m 的修正"）：
     - **σ_θ 和 P**：σ_θ 取模型 JSON 的 `yaw_sigma_deg`，即 `reconstruct` 报的 GPS/罗盘融合 σ 再平方和加 3° 的系统误差底（`Params.yaw_systematic_sigma_deg`）；模型没报时取 6.7°（即旧的 ±20°）。P 由 `outline_symmetry_period()` 从轮廓量出：洗礼堂 44°、圣母教堂 85°、勃兰登堡门 177°、亚琛 360°（无对称）、比萨斜塔 0°；规则正八边形量出 36°（采样点在 1 m 内落回轮廓的盆地从 36° 开始，比名义的 45° 保守）。窗口 < 2° 时只搜平移。
     - **粗搜索**（`_placement_grid`）：窗口内约每 2° 一个转角 × 平移 ±25 m 每 1.5 m 一格，在 300 个墙高点上算"截断在 3 m 的平均点距"，取最好的 8 个局部极小值，再加上配准原位，作为 ICP 起点。网格固定，不依赖配准原位：SfM 稍有变化，同一批盆地也都还能找到（验证者重跑洗礼堂 E#14 时，旧的"每 4° 一个转角、只从原位和质心出发"漏掉了 −1° 的更好盆地）。
     - **ICP**：只用最近的 70%、且离轮廓 ≤ max(1 m, 3 × 中位距离) 的点对。只按 70% 截断时，贴着轮廓的邻楼、树或穹顶（占点数 35%）会把合成墙的转角拉偏 3–7°。平移不在迭代里截断，只要求最终解的墙移动 ≤ 25 m（在吸附后落在轮廓 3 m 内的墙点处量，不在全部墙高点的中位数处量）。各个解按"截断在 3 m 的平均点距"排序，不按中位数：中位数看不见少数点，而一小段端墙常常正是区分柱廊相邻两跨的证据。
     - **歧义就拒绝**：(a) 另有一个解也通过逐边核验，截断平均距离在最优解的 125% + 0.1 m 以内，而且会把照片在墙上挪 ≥ 1.5 m（墙点位移的 90 分位）或转 ≥ 2°。轮廓能修尺度时（窗口模式，中位距离降 ≥ 10%），每个候选解再做一次有界的尺度修正（±15%），刚体版和缩放版一起排序、一起比：尺度不对的模型没有一个刚体解贴得好，它的几个刚体解转角、平移各不相同，却不是不同的位置（一个小了 12% 的盒子曾因此被当成歧义）。第一版试过"缩放顺带转了 > 2° 就拒绝"，它把小了 10% 的盒子也拒了，已删掉；它原本拦下的圣母教堂 SW#9 现在由下面的"贴得太松"拦下。(b) 把最优解绕墙转 ±2°、±3.5°、±5°（平移重新拟合）仍在这个余量内，并且照片挪 ≥ 1.5 m；或者转到 ±5° 还在余量内。这说明偏航谷太平，轮廓定不住偏航。(b) 是第二轮加的：圣母教堂 SW#24、#25（20–30 张照片）的最优解就在这样的平谷里，比参考多转了 3–4°，SW#24 当时给 12 面墙上了色；对的 SW#11/14/15 转 2.5° 以内拟合就出了余量。
     - **墙贴得太松也拒绝**：吸附后，落在轮廓 3 m 内的墙点到轮廓的平均距离（截断在 3 m）> 0.45 m，轮廓就定不住偏航。圣母教堂 SW#9（8 张照片，缩放 0.926 后转了 −2.2°）、#20、#24、#25 的这个值是 0.50–0.55 m，都比参考差 3–5°；对的 SW#11/14/15 是 0.30–0.34 m。这条门槛只在一栋建筑的 7 个模型（3 次 SfM）上标定过。
     - **其他拒绝**：最优解离窗口边 < 1°；吸附后相机到墙的距离与照片自己的 EXIF GPS 到墙的距离之比（逐相机中位数）偏离 1 超过 max(5%, 1.5 个标准误)；轮廓要的尺度修正顶到 ±15%；轮廓没修尺度、而 GPS 尺度不确定度 > 15%。
     - **只搜平移时**，3σ_θ > 5°、或 3σ_θ 让照片绕轮廓挪 > 1.5 m（半径 × 转角），就拒绝。这时轮廓查不了偏航，只能信配准报的 σ_θ；验证者的对抗用例里，近圆轮廓上 47 个通过有 34 个是错的，最大偏 21°。按 3° 的系统误差底，3σ_θ ≥ 9°，所以比萨斜塔现在一律被拒，要等更准的偏航来源（例如 VISUAL_LOCALIZATION 的视觉定位）。
   - **第三轮（2026-10-24）新增**，起因是验证者查出第二轮仅有的 3 个真实通过（圣母教堂 SW#11/#14/#15）里有 2 个按相机中心标准是错的，SW#14 当时的贴图还整体偏高 3–4 m：
     - **相机的位移也算**（`snap_ambiguity_cameras`）：上面 (a)(b) 里"把照片挪 ≥ 1.5 m"之外，再加"把相机挪 ≥ 1.5 m（中位数）"。转角谱另外试一个"让相机挪 1.5 m 的转角"（相机离墙 D 米时为 1.5/D 弧度，最多 2°）。相机离墙 70–90 m，转 1° 墙上几乎不动，相机却挪 1.2–1.6 m；对的配准要求相机在 1.5 m 内（见下面的判定），所以轮廓要能把偏航定到约 1°、把尺度定到约 2%，才敢用照片证据。圣母教堂 SW#11 转 −1.2° 后拟合 0.38 m（最优 0.30 m，仍在余量内），因此现在拒绝；勃兰登堡门 E#47（v0 那次 SfM）只有靠这条才拦得住：它的刚体解和缩放 0.924 的解在墙上只差 1.1 m，相机却差 3.2 m，按参考它的墙点偏 7.8 m。
     - **尺度谱**（`snap_scale_steps`, `snap_scale_gps_sigmas`）：把最优解绕墙缩放 ±3/6/10%（平移重新拟合），只试在 GPS 拟合尺度 σ 的 2 倍以内的那几档（σ 未知就都试）；拟合仍在余量内、又把照片或相机挪 ≥ 1.5 m，就算尺度没定住，拒绝。点到轮廓的距离对"缩短"几乎不敏感（墙点仍在边上），所以只拍到两面相邻墙的 L 形模型，尺度基本只能靠 GPS：34 m × 13 m 的 L 大 7% 时，最远端的照片偏 2 m（验证者 street_L：240 例里 76 个这样通过、全错）。按 2σ 判是因为 1σ 会放过 1.4σ 的误差（7% / 5%）。
     - **倾斜检查**（`camera_tilt_check`, `snap_max_tilt_shift_m` 1.5 m）：吸附只绕竖直轴转，模型若本来就倾斜，平面上的各项检查都看不见，照片却在 40–250 m 外的墙上整体偏高或偏低。拍照的人大致站在同一高度，所以对未标记相机的中心拟合一个稳健平面 z = a + g·(xy − c)（离群 > max(3×1.4826 MAD, 0.75 m) 的相机剔除：塔上、露台上拍的），它在墙点处推出的竖直偏移 |g·(墙 − c)| 的 90 分位，加 1 个标准误（高度离散下限 0.25 m），必须 ≤ 1.5 m；相机 < 5 台或排成一条线（测不出朝它的倾斜）也拒绝。圣母教堂 SW#14 推出 3.04 ± 0.27 m（对参考的实际倾斜 2.79°）、SW#15 2.55 ± 0.28 m（2.18°）、SW#11 0.47 ± 0.31 m（0.62°）。真的上坡的街道也会被读成倾斜而被拒，这是安全的一侧。洗礼堂立面模型的相机高度离散很大（拟合斜率中位数 8.4°，而对参考的倾斜中位数只有 0.86°），这条检查在那里会误拒，不过那些模型本来就因为别的原因被拒。
     - **没有相机看得见的面**（`registration_check` 的 `cameras_xy`、`unseen_points`）：一条有投票权的边，外侧 ≥ 1 m 处一台相机也没有时，检查它 3 m 内、墙高下半段的点：把点朝每台相机挪 3 m（允许立面在画到勒脚的轮廓里面 3 m），如果挪完仍在建筑内、或从那里到相机的视线穿过轮廓，这台相机就看不见它。这样的点 ≥ 20 个且 ≥ 该边点数的 30% 时，整次吸附直接拒绝：每台相机都得穿过整个体块才看得到它们（滑到体块背面、把街对面邻楼的立面挪到这面墙上）。只看下半段，是因为从墙外越过屋檐看到的屋顶点也会被判成"看不见"。
     - **σ_θ 的下限也在风格化里**（`snap_min_yaw_sigma_deg` = `Params.yaw_systematic_sigma_deg` = 3°）：模型 JSON 报的 σ_θ 比这小也按 3° 用。验证者把 σ 报小三分之一时，只搜平移的模式在近圆上放过了 12–16° 的偏航误差。

### 3.3 观测判定：哪些墙、墙上哪些地方算"拍到了"

D29 起观测判定不再决定颜色，只决定两件事：**哪些墙算拍到**（`WallObservation.observed`，GLB 墙节点的 `observed`）和**墙上哪些纹素算拍到**（观测掩码 M，`observation_mask()`）。用到它的地方：

- D24 立面凹凸只在拍到的墙上量，只建在拍到的那一段里、观测纹素上（STRUCTURE_FIRST §2.4.7 的 G-R5）；
- 结构指标的拍到面积（`structmetrics` 的 `photographed_area_m2`，以及由它算出的 `detail_coverage`）；
- 查看器第一眼朝向哪一侧（§3.8）。

判定的算法和 D29 之前逐位相同：`tests/test_d29_pins.py` 钉住了掩码、每面墙的判定和墙段切分，删代码的每一步都和删之前的基线逐项比过【D29】。

**一面墙算拍到**（`observe_walls()`，再加两次掩码检查），下面几条都要满足：

1. ≥ 2 台已注册相机（`min_wall_cameras`）各看到这面墙 ≥ 15% 的可见格：相机在墙前方，视线和墙法向夹角 ≤ 72°，投影落在图像内，不被体块挡住；
2. 墙面 0.75 m 带内有 ≥ 20 个 SfM 点，且 ≥ 1 点/m²；
3. 拟合的墙面平面离这个面 ≤ 1.5 m、≤ 8°，而且不在轮廓外（§3.2 第 3 条）；
4. 不是"高度待定"矮台（D13）的墙，也不在逐边残差门 G11 超限的边上（STRUCTURE_FIRST §2.2）；
5. 几何掩码（下面第 1 步）覆盖 ≥ 10% 的墙（`min_observed_fraction`）；去掉天空、植被、整理以后的观测掩码仍覆盖 ≥ 10%。

配准被拒时没有一面墙算拍到。

**观测掩码**（每面候选墙一张，16 px/m，长边 ≤ 512 px）。每一步只会从掩码里去掉纹素，不会加：

1. **几何掩码**（`facade_orthophoto()`）：把这面墙最好的 ≤ 24 张照片投到拟合的墙面上。一台相机的样本在两种地方丢掉：体块挡住这面墙的地方；墙前 > 1.5 m 的 SfM 点挡在视线上的地方（每台相机一张深度格，长边 128 格，一格里 ≥ 3 个三角化质量好的点才算挡住；结构路径上每个点挡住半径 0.3 m 的圆）。然后每张照片一组曝光增益（向混合结果迭代 2 次，限 0.5–2.0），逐纹素取加权中值。一个纹素要 ≥ 2 张照片和混合结果一致（0.4 m 窗口平均后 RGB 距离 ≤ 60，且 ≥ 50% 的视角一致），并且墙面上有 SfM 点支撑（0.75 m 带内，膨胀 1.5 m）；再做 0.5 m 的开、闭运算。这一步用到照片的颜色，但只用来判断这些照片看到的是不是同一面墙：路人、视差重影、点云没抓到的遮挡物都对不上。颜色本身不进模型。
2. **场景归一**（`scene_observation_norm()`）：相信相机的白平衡。只有地标最浅的材料在曝光最好的四分之一视角里本身是中性色（C\* ≤ 4）时，才把白平衡调到让它保持中性（STRUCTURE_FIRST §2.5 第 7 条）；每面墙的混合先锚回原始视角的逐纹素中值（第 2 条）。曝光提升默认关（D21）。摘要的 `observation_norm` 记下用了哪些增益。
3. **去掉天空和植被**（`clutter_mask()`，在归一后的 CIELAB 里按 25 cm 平均判断）：又蓝又亮、或浅蓝而平滑，并且连到观测区上半部的块是天空；黄绿色的叶子（≥ 0.5 m²）和阴影里又暗、纹理又重的橄榄色叶子（≥ 1 m²）是植被。去掉以后做 0.5 m 的开运算。
4. **去掉漏网的天空**：在 8 px/m 的工作图上，彩度明显高于墙（≥ 14，且比墙高 8）的浅蓝"点缀"，如果墙本身不是蓝色，就算天空（从转角外、拱廊里看到的天空）。
5. **整理**（`tidy_mask()`）：去掉 < 1 m² 的孤岛，边缘用只减不加的模糊软化。< 0.5 m² 的洞只在模糊时临时桥接，免得洞边被吃掉；洞本身仍不算拍到。
6. 剩下的不到 max(20 个纹素, 0.5 m²)，或工作图上不到 8 个像素时，掩码为空，这面墙不算拍到。

**墙段**（`wall_pieces()`）：拍到的墙按掩码里有观测的列切成竖条。中间一段是"拍到的那一段"（节点 `observed: true`）；两端宽 ≥ 1 m（`strip_min_m`）的没拍到的竖条各成一个节点（`observed: false`）。两段拍到的墙段之间的倒角也标拍到。所有墙段都是素模，外观来源都是 `default-style`（§3.9）。

**独立复核**（`audit_model`，§3.9）：对观测掩码里抽样的纹素，用点和相机做线段遮挡检验（和建掩码用的深度格是两种方法）；被挡的比例全楼 ≤ 5%、每面墙 ≤ 20%，否则不发布。

**局限**：完全没有 SfM 点的遮挡物，几何掩码挡不住（D29 前的合成红棚子测试里约 20% 漏进了贴图【原型】）；它会让一小块其实被挡住的墙算拍到，影响的是 D24 能在哪里建、拍到面积有多大。常年站着人的墙脚（洗礼堂"天堂之门"下方）中值也去不掉，多视角一致那一条通常会把它判为没拍到。

**视觉定位的照片**：定位成功后就是一台普通的已注册相机，能增加看到墙的相机数；它带不来新的三角化点，第 2 条保证它不能单独让一面没有点云的墙算拍到。

**D29 删掉的**：D12 补洞；"锁定 / 部分解锁 / 已解锁"的墙状态和解锁计数；掩码外涂素模纹理的贴图；按掩码切出的"已拍条"贴图。

### 3.4 立面正射图（只用来定观测掩码）

1. 把墙面按纹素铺成网格（16 px/m，长边 ≤ 512 px），用已知相机位姿把每个纹素投到每张照片上取色（OpenCV `remap`）。
2. 曝光归一和混合见 §3.3 第 1 步；混合的权重 = 可见比例 × cos 视角 × 分辨率。
3. **正射图永不发布**：它只在风格化进程的内存里，用来定观测掩码，不写进 GLB，也不再写调试图（`scripts/stylize_model.py` 只出俯视草图）。D29 前它是墙面贴图的来源。

### 3.5 简化：立面程序（D29 删除）

立面程序（从照片里认出门窗、横带、条纹壁柱，再画成贴花和贴图）D29 前只做到"三层分解 + 门窗规整"，随上色一起删掉。立面上的结构现在只有几何：D24 量出的凹凸（`crowd3d/relief.py`，STRUCTURE_FIRST §2.4.7），每个元素都带证据记录，只建在拍到的墙上。

### 3.6 形状与屋顶

→ 结构优先：屋顶的形状来自地图积木（STRUCTURE_FIRST §2.4），不由覆盖率决定。

- **屋顶**：没有一个屋顶算拍到（D29）。每块积木的屋顶是一个素模节点（`roof-<i>-clay-<f0>`）；外轮廓拉伸路径上的金字塔顶，坡面和中性平盖各一个节点。每个屋面记点覆盖率（`roof_coverage()`：1 m 网格里有屋顶点的格子比例）和面积，只供查看，不决定外观。外轮廓拉伸路径上，覆盖 < 40% 的金字塔面不按点云造坡，改成中性平盖。
- **D29 前后的变化**：D29 前屋面按 SfM 点的颜色和覆盖率上色，拍到的屋顶块按颜色拆成单独的节点，还有贴在屋面上的颜色贴片（`roof-patch`）。删掉以后，只有照片对齐的参考场景有变化：屋顶节点合并（洗礼堂 corrected 8 → 3，亚琛 40 → 22，贴片节点 2 / 6 → 0），`photographed_area_m2` 只算墙（洗礼堂 corrected-d24 1519.5 → 1095.1 m²，`detail_coverage` 0.3088 → 0.4284；亚琛 corrected 1940.7 → 1285.7 m²）；墙、立面凹凸、D15、D25 和结构普查逐项不变【D29】。
- **圆角**：外轮廓拉伸路径上，体块转角倒圆，半径 = clamp(1.5% × 直径, 0.3 m, 1.2 m)，3 段。结构路径不倒角：积木的墙和屋顶原语要边对边地合上。
- **立面凹凸**：只有 D24 量出的几何（§3.5），凹进去的做成墙上的洞加侧面和背面（拱用 8 段半圆），凸出的做成盒子。
- **调色板**（D29 删除）：30 多种自有颜色、色族、洞口档和样式令牌都删了，GLB 的颜色表只剩三种素模色（§3.7）。

### 3.7 网格与 GLB

1. 原型自带零依赖的 GLB 写出器（`write_glb`），**写出时必须带 NORMAL**（几何草案用 trimesh 导出时没打开 `include_normals`，toon 材质下整楼全黑【几何】）。GLB 里**没有图片、贴图和纹理坐标**：`audit_glb` 见到任何一样都不发布。
2. **节点**：每组面一个节点。extras 带：
   - `kind`（`wall` / `corners` / `roof` / `roof-cut` / `base`）、`wall`、`part`；
   - `provenance` {`outline`, `height`, `appearance`}，`appearance` 恒为 `default-style`（§3.9）；
   - `observed`：只在墙段和两段拍到的墙之间的倒角上可能为 true（§3.3）；
   - 屋顶的 `coverage` 和 `area_m2`；结构积木的 `geometry`、D15 的采用和 D25 的纠正；立面凹凸的 `relief` 记录。

   材质是平涂的素模色，材质 extras 写颜色名（`clay`、`clay-roof`）。
3. **scene extras**：`generator`、`frame`、`landmark`、`attribution`（OSM 署名和照片署名：产品作业写"Placement and photo-measured detail from this landmark's check-in photos (Crowd3D contributors)"，脚本和基准写 Wikimedia Commons 照片的那一句）、`provenance_values`、`registration`、`snap`、`prior`、`style`（颜色表只有 `clay`、`clay-hatch`、`clay-roof` 三项，`STYLE_VERSION` 2）、结构优先时的 `structure`、`structure_lines`、`relief` 和 `structure_metrics`。
4. **体积和三角形预算**（设计；原型没有单独检查）：每个模型 gzip 后目标 ≤ 150 KB，硬上限 300 KB（Q13）；三角形 ≤ 20k（不含查看器生成的描边），这个量级不做 LOD，也不用 Draco、meshopt。D29 去掉贴图后 GLB 变小了：洗礼堂参考 corrected 的 GLB 79.6 → 58.2 KB；基准里合成集最好模型的 `style_glb_kb_gz` 汇总值 21.0 → 3.1 KB【D29】。每次浏览的下载按 0.2–0.3 MB 估（§6）。
5. **隐私**：GLB 里不放照片 id、用户 id 和相机位姿，只放计数。D29 前墙节点里调试用的贡献照片列表随上色删掉了。照片位姿另走接口（D30，任务 #87），要先定隐私规则。

### 3.8 查看器

`web/stylized.html`、`web/stylized.js`：

- **材质**：每种节点一个带斜纹的卡通素模材质（`MeshToonMaterial`，明暗档来自画风）。屋顶用画风的 `clay.roof`，其余（墙、倒角、屋顶切面、底面）用 `clay.wall`。GLB 里的材质颜色、贴图、纹理坐标和 `locked` / `observed` 标记都不用来上色，所以 D29 之前写的、带照片颜色的旧 GLB 也显示成素模；旧 GLB 里贴在屋顶上的颜色贴片（`roof-patch`）不画。
- **描边**：固定像素宽的反壳剪影，加 `LineSegments2` 粗折痕线；屋脊、斜脊按模型列出的结构线画，约定值的屋顶形状（D17）画虚线。颜色和粗细来自画风（或不要描边），地址参数 `outline=<px>` 可以覆盖宽度。
- **光照**：半球光加一盏主光，数值来自画风。
- **兜底**：没有法线时调用 `computeVertexNormals`。
- **取景**：第一眼朝向拍到的墙那一侧（`preferredBearing`，只读墙节点的 `observed`）；没有拍到的墙时朝 140°（`DEFAULT_BEARING`）。地址参数 `bearing`、`elev`、`zoom` 可以覆盖。
- **交互**：点一块积木出来源卡片：形状的状态（地图、约定、照片核验、照片量出（自动采用）、照片纠正（D25）、高度待定）、轮廓和高度的来源、立面凹凸的元素和证据（D24 写"照片点云量出（D24）"）、倾斜（D25-T）。卡片不再写外观（D29 后都是素模）；高度来源 `default-style` 写"默认样式（没有实测，也没有标注）"。OSM 署名常驻，不能藏在菜单里（OSMF 署名指南）。
- **面板**：墙数、屋顶面数、立面凹凸元素数（没有时不显示）。
- **画风**（D7，已拍板）：`web/themes/<id>.json`，地址参数 `theme=<id>`，面板里有下拉框。D29 后画风只有素模色（`clay.wall`、`clay.roof`、`hatch_shade`）、墨色 `ink`、描边、卡通明暗档、光、背景、地面和渐变；校验器只查斜纹看得见（ΔE00 ≥ 3，按查看器真实的光照算）和格式。参考画风 4 个：明快扁平（默认）、绘本粉彩、黄昏渐变、蓝图线稿。详见 `docs/ART_DIRECTION.md`。
- **默认画风的素模和 D29 前一样**：同一个素模 GLB 的截图逐像素相同，只少了"待解锁"牌子和墙上的虚线框【D29】。
- **留给照片位姿图层**（D30，任务 #87）：CSS2DRenderer 的 `.labels` 覆盖层、`bearingOf`、画风的 `ink`。
- **D29 删掉的**：贴图的按画风逐纹素换色、调色板规则、素模色对实拍色的 ΔE00 ≥ 7.5 校验、"待解锁"牌子和虚线框、补洞的卡片行、"屋顶已拍 X%"和"已解锁立面 N/M"的标签。

### 3.9 "不许猜"怎么强制执行

→ 结构优先：来源枚举加 `photo-fitted`、`photo-fitted (auto)`（D15 自动采用，查看器写"照片量出（自动采用）"）、`photo-corrected (auto)` 和 `photo-corrected (auto, lower bound)`（D25）、`s3db-shape-default`、`osm-s3db-support` 等；立面凹凸的元素记录另带 `photo-measured` 或 `photo-measured (points, D24)`。结构 QA 门 G1–G12 和这里的检查一起决定能不能发布（`qa.passed` 里的 `structure`）。见 `docs/STRUCTURE_FIRST.md` §2.7、§2.8。

**在代码里（构造保证）**：

## 4. 美术风格指南

> **D7 已拍板**：画风由产品负责人定，写成一个 JSON 文件就能换，格式、校验和 4 个参考画风见 `docs/ART_DIRECTION.md`。D29 起画风只管素模色、描边、明暗、光和背景；形状语言（4.1、4.3）仍由风格化作业决定。

### 4.1 五条原则

1. **剪影优先**：认不认得出先看体块和屋顶，立面细节排第二。
2. **少即是多**：屏幕上小于 6 CSS px 的元素不画。
3. **全部圆润**：基本形只有圆角矩形、圆、圆角三角形。这和 Duolingo 公开描述的形状语言是同一种精神（用最少的形状，圆润友好），但**我们不用 Duolingo 的色值、角色、字体和素材，宣传里也不写"Duolingo 风格"**（画风本身一般不受保护，但商业外观和商标受保护）。
4. **颜色不来自照片**（D29）：整栋是素模，素模色由画风决定。
5. **看得出哪里是事实、哪里是照片量出的**：来源卡片写明每块积木的形状来自哪里；约定值的屋脊画虚线（D17），"高度待定"矮台是 3 m 高的占位（D13）。

### 4.2 素模色（调色板 D29 删除）

D29 删掉了自有调色板（30 多种颜色、色族、洞口档、样式令牌和它的校验）。剩下的只有素模色：

- GLB 的颜色表三项：墙 `clay` (228, 232, 238)、斜纹 `clay-hatch` (208, 215, 226)、屋顶 `clay-roof` (214, 220, 229)。
- 查看器按画风显示，不读 GLB 里的颜色。默认画风墙 #c8d1df、屋顶 #c9d2e2，斜纹 = 素模色 × 0.84（线性光），和 D29 前素模墙的样子一样（`docs/ART_DIRECTION.md` 第 1、3 节）。

### 4.3 形状语言

| 元素 | 规则 |
|---|---|
| 体块转角 | 外轮廓拉伸路径：圆角 r = clamp(1.5% × 体块直径, 0.3 m, 1.2 m)；结构路径不倒角（§3.6） |
| 屋顶 | 按 OSM `roof:shape` 的原语（STRUCTURE_FIRST §2.4.1），做不出来按退化链退 |
| 立面凹凸 | 只有 D24 量出的几何：横带、壁柱、退台、拱券开间、门窗洞等（STRUCTURE_FIRST §2.4.7） |
| 最小元素 | 默认取景下 ≥ 6 CSS px（设计目标） |

### 4.4 描边

| 描边 | 宽度和颜色 |
|---|---|
| 剪影 | 固定像素宽的反壳，宽度和颜色来自画风（`outline.width_px`、`silhouette_color`） |
| 折痕线（屋面之间、墙和屋顶之间的折边） | 默认是剪影宽度的 0.7 倍，至少 1 px（`crease_width_px`、`crease_color`） |
| 约定值的屋脊、斜脊（D17） | 虚线 |

### 4.5 光照

- 半球光加一盏主光，颜色和强度来自画风；卡通明暗 2–6 档（默认 3 档）。
- 设计目标：主光跟着相机走，保证任何视角下相邻面至少差一档明暗；手机上不开实时阴影贴图（软件渲染下占帧时间 22–33%【产品】），改为按轮廓烘焙一张地面软阴影。

### 4.6 各种状态长什么样

| 状态 | 条件 | 外观 | 地标页标签 |
|---|---|---|---|

### 5.4 诚实的局限

4. **没有 SfM 点的遮挡物**挡不住（§3.3），会让小块被挡住的墙算拍到。
5. **样本很小**：阈值（遮挡余量、平面容差、核验比例、吸附门）都在两座参考建筑和开发集上调的，属于样本内结果。
6. **和本文设计还不一致的地方**：没有轮廓时从点云描轮廓拉伸体块（§3.1 要求只显示已观测墙段）；Wikidata 高度仍会拉伸塔状轮廓；Q12、Q13 没做；体块登记表的冲突策略和滞后没做。

- **即使取高端，1 万个地标时算力每月也在 $1k 左右，流量接近 0；人工审核和数据库才是大头。**

**单位经济指标改为**："每个已发布立面的审核分钟数 + CPU 分钟数"，取代 ARCHITECTURE §10.1 的"每个已发布立面的 GPU 成本"。

**可选的额外算力（公司付费，都不含图像生成）**：SAM 3 概念分割 < $0.001/立面【估算，ML】（立面程序用，D29 后不需要）。VLM 文案：Claude Haiku 5.5（$0.10 / $0.50 每百万 token）默认开着自适应思考、effort 默认 medium，思考输出也按输出计费，所以调用时 effort 设 `low`、`max_tokens` 设 1024；按每次约 2k 输入 token（一张正射图加提示）算，每立面约 $0.0004–0.0007；用 Claude Sonnet 5.5（$2 / $10）约 $0.006–0.014。1 万个地标 × 平均 10 面墙 × 每月重算一次 = 每月 10 万次，约 **$40–70（Haiku）到 $600–1,400（Sonnet）**【估算】。

### 7.2 指标

**"对"的定义**（`style_registration_right / wrong`，指标第 5 版起）：过了配准门、并且至少 3 台相机有参考位姿的模型，四条都满足才算对：相机水平中心离参考的中位数 ≤ 1.5 m；还需要的转角 ≤ 5°；尺度差 ≤ 10%；墙点还要挪动的 90 分位 ≤ 1.5 m（取二维和三维里大的那个，倾斜也算）。细节和理由见 §3.2。

### 9.3 开放的技术问题

1. **`prior_only` 模型的尺度和倾斜**：NE 立面模型带尺度吸附只修到 0.923，檐口仍 24.5 m，原因没查清【几何】。在查清之前，`prior_only` 模型不贡献高度和照片证据。
2. **OSM 分件高度与点云估计不一致**：亚琛 14 个有 ≥ 30 个点的分件里，5 个和 OSM 相差 ±4.5 m 以内，其余多数差 +7 到 +16 m，另有一个只有 37 个点的件差 −12 m【几何】。几何草案测得参考模型相对 OSM 的尺度是 1.022；但原型吸附到轮廓时测出亚琛模型比轮廓小约 10%（尺度修正 1.10）【原型】，两者对不上。结构优先的 D15、D25 有自己的尺度规则（STRUCTURE_FIRST §2.4.2、§2.4.8）。
3. **识别度**：曲面壳体（悉尼歌剧院：分件没有高度，`roof:shape` 是 round、circular、spherical，后两个不是标准值）、哥特镂空、雕塑型地标，用拉伸体块未必认得出；D29 后靠颜色认的地标也只剩形状。悉尼歌剧院这类只能由馆员按公开尺寸手工建模（来源 `curator`），或显示低体块加"特殊几何待定"，**不用图生 3D**。
4. **树、脚手架、玻璃幕墙**：树和脚手架会让墙算拍到、影响 D24（靠植被规则、点云和多视角一致去掉一部分）；玻璃幕墙没有特征点、没有点支撑，不算拍到。
5. **CPU 建图超线性**：50 张到 100 张建图时间涨了约 16 倍【产品】，成本上下界差约 2 倍；n ≥ 300 时 global mapper 的实际速度要测。
6. **真机性能**：只有软件渲染的数字。

## 附录 D：术语

每个术语一行，按在正文里第一次出现的大致顺序。

**本文自己的说法**

- **素模**：没有照片贴图的体块，浅冷灰色加淡斜纹（§4.2）。D29 起模型的每个面都是素模；原文有时说"陶土色""白坯""石膏模型"，都是指它。
- **观测掩码（M）**：一面墙上满足 §3.3 全部条件、算"拍到了"的那些纹素。只决定哪些墙、墙上哪些地方算拍到，不决定颜色。
- **纹素**：观测掩码（和它背后的正射图）上的一个像素，对应墙面上的一小块（原型是 1/16 m 见方）。
- **正射图**：把多张照片投到墙面平面上、拼成的一张"正对着墙拍"的图。只在风格化进程的内存里用来定观测掩码，永不发布。
- **拍到（`observed`）**：一面墙满足 §3.3 的条件，算照片拍到了；D24 只在这些墙上量，结构指标的拍到面积只算它们。屋顶从不算拍到（D29）。
- **配准门**：吸附到轮廓以后的一组检查（§3.2），通过了才用照片证据（D15、D24、D25）。地标页的"素模（照片已对齐）"/"素模（照片未对齐）"说的就是它。
- **吸附**：把重建出来的模型平移、旋转（必要时缩放）到 OSM 轮廓上。**逐边核验**：吸附后逐条轮廓边检查点云是不是真的贴在边上（§3.2）。
- **来源（provenance）**：每个面记下"轮廓、高度、外观分别来自哪里"（外观恒为 `default-style`）；照片量出的数字另带证据记录。
- **画风（主题）**：查看器怎么画一个模型：素模色、斜纹、墨色、描边、明暗档、光、背景、地面。一个画风就是 `web/themes/` 里的一个 JSON 文件（`docs/ART_DIRECTION.md`），只换外观，不改测到的东西。
- **【几何】【ML】【产品】**：三份草案作者（几何与风格化、生成式模型政策、产品／美术／成本）各自实测的数字；【原型】【原型 v1】【本文】【估算】【待核实】见文首。
- **原型里的英文名**：wall 3 = 原型按轮廓边编号的第 3 面墙。

**地图与数据**

- **OSM（OpenStreetMap）**：志愿者绘制的开放地图。**ODbL**：OSM 数据的许可证，用了要署名，派生出的数据库要按同样条款公开。**Produced Work**：ODbL 里"由数据库产出的作品"（比如一张地图、一个 3D 模型），规则比派生数据库宽松。
- **S3DB（Simple 3D Buildings）**：OSM 里描述建筑三维形状的一套标签，把一栋楼拆成多个**分件**（`building:part`），每个分件带高度和屋顶形状（`roof:shape`）。
- **Wikidata**：维基百科的结构化数据库；P2048 是"高度"这个属性；条目里的值有 rank（preferred 优先、normal 普通、deprecated 已弃用）。
- **ENU**：以地标为原点的局部坐标，x 向东、y 向北、z 向上，单位米。
- **georeg_level（配准等级）**：`full` 表示模型的位置、朝向、尺度都由 GPS 等定好了；`prior_only` 表示只有粗略先验，不可靠。
- **Commons（Wikimedia Commons）**：维基共享资源的开放照片库，每张照片有自己的许可证。**MegaDepth-X**：本项目评测用的一组带参考模型的照片集。

**重建与几何**

- **SfM（运动恢复结构）**：从多张照片同时算出相机位置和稀疏的三维点云；本项目用 COLMAP。**SIFT**：经典的图像特征点算法。**MVS（多视角立体）**：在 SfM 之后算稠密深度。
- **RANSAC**：反复随机抽样、找出"大多数点都同意"的那个模型（例如一个墙面平面），用来抵抗离群点。
- **ICP（迭代最近点）**：反复把一组点往另一组点或线上靠，求出最佳的平移和旋转。
- **IoU（交并比）**：两个区域重叠部分除以合起来的部分，1 表示完全重合。
- **Hausdorff 距离**：两条轮廓之间"最远的那一处"相差多少米。
- **bootstrap**：反复重采样数据、估计一个数的波动范围（置信区间）。
- **p95、p90**：第 95、90 百分位数，例如 p95 帧时间 = 95% 的帧比它快。
- **LOD（细节层次）**：远处用简化模型、近处用精细模型的做法；本文的模型小，不需要。

**颜色与渲染**

- **CIELAB、L\*、ΔL**：一种按人眼感受设计的颜色空间；L\* 是明度（0 黑到 100 白），ΔL 是两个颜色的明度差。
- **ΔE76、ΔE00**：两个颜色的感知差异。ΔE76 是 CIELAB 里的直线距离，ΔE00 是更贴近人眼的改进公式；大约 2 以下人眼难分辨，10 以上一眼能分开。
- **色度**：颜色的鲜艳程度，接近 0 就是灰色。**色相**：红、黄、绿、蓝这类"是什么颜色"。
- **glTF / GLB**：三维模型的开放格式，GLB 是它的单文件二进制版本。**extras**：glTF 里留给应用自己写附加信息的字段。
- **toon 着色、gradientMap**：卡通渲染，把连续的明暗压成几档；gradientMap 是规定这几档亮度的小贴图。
- **CSS px、DPR**：网页里的逻辑像素；DPR（设备像素比）是一个 CSS px 对应几个物理像素，手机通常是 2–3。
- **SwiftShader**：在 CPU 上模拟显卡的软件渲染器，CI 里用来跑查看器，速度不代表真机。
- **3DGS（3D 高斯泼溅）**：旧方案里的照片级渲染技术，要 GPU，本文把它移出了核心路径。

**模型与成本**

- **生成式模型**：能"画出"新内容的模型（扩散模型、图生 3D 等）。**inpainting / outpainting**：在图里补画缺失的部分 / 往图外扩画。**img2img**：以一张图为起点生成另一张图。
- **SAM（Segment Anything）**：Meta 的通用分割模型，给一个点或框就能圈出物体。**DINOv2**：Meta 的通用图像特征模型。**CMP**：一个带标注的立面数据集。**VLM**：能看图说话的语言模型。**EgoBlur**：Meta 的人脸和车牌打码模型。
- **vCPU·h**：一个虚拟 CPU 核跑一小时，云上按它计费。**spot**：云厂商的可被随时收回的便宜实例。**CDN**：内容分发网络，按流量计费。
