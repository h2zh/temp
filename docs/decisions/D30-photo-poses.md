# D30：别人照片的拍摄位置（2026-11-03 决定，11-04 验证）

> 原来是 README 的一节，D34 C 部分第 2 步（2026-11-13）搬到这里：文字没有改，只把指向 README 别的章节的话（"见上面某一节"）换成了链接。全部决定的索引在 [README.md](README.md)。

> **D32（2026-11-05）改了这一节的同意规则**：上传必须同意用户协议（D33 起在登记时同意一次），每张通过、确定了位置和朝向的照片都公开（位置和照片本身），以前的照片一次性迁移成同意。下面"同意和撤回"里的勾选框、`share-location-v1` / `v2` 和"以前的照片都算不同意"都已删掉。取整、快照、扣下的规则和视觉定位没有变。见 [D32 的记录](D32-terms-compare-appearance.md)。

**产品负责人的决定**（原话："别人照片的位置取整到 1m、朝向取整到 1°，并且不返回用户 ID。只要用户同意分享位置信息，我们必须不能浪费（做出粗糙的推断）"）：

- 别人看到的照片位置取整到 1 米、朝向取整到 1°，不返回用户 ID。
- 只显示上传者明确同意分享位置的照片：默认不同意，以前的照片都算不同意。（D32 改了：上传必须同意用户协议，以前的照片迁移成同意。）
- "不能浪费"，开发这边的理解：
  - 不显示粗糙的推断，例如"朝着地标中心"这种猜出来的朝向；
  - 每张同意的照片都尽量放准：在已发布的模型里就用模型重建出的位姿，不在就用视觉定位放进地标已存的地图；手机 GPS + 罗盘只作标明了的后备；
  - 放不准就不显示。

**同意和撤回**（D30 的做法；D32 把可选的勾选换成了必须同意的用户协议，见 [D32 的记录](D32-terms-compare-appearance.md)）：

- D30 时地标页上传区有一个勾选框"公开这些照片的拍摄位置、朝向和视角"，默认不勾，同意记成 `share-location-v2`（v1 的说明少写了一条风险）。D32 删掉了这个勾选框和这两个版本。
- 说明里写的两条风险，D32 的协议和上传说明都保留了：这里上传的人少时，别人能猜出哪几行是你的；任何人都能用手动重建或几张上传让下一次建模很快开始。
- 只有通过校验的照片才记下同意（D32 起记的是协议版本 `terms-v1`）。
- 上传结果给每张公开的照片一个撤回凭证，浏览器把它存在本机。地标页可以撤回一张或全部，撤回马上生效（`POST /api/photos/{id}/share_location`；D32 起同时撤下照片本身）。D30 时凭证只在上传的响应里给一次；D34 第 2 步起，上传用的登记可以向服务器重新要（`POST /api/contributors/photos`），也可以直接凭登记撤回。
- 凭证由部署密钥算出，所以密钥（数据目录里的 `public_id.salt`）要和数据库一起备份。
- 共同完成者只列昵称，不给每人的照片数，免得和公开的位置对上号。

**别人看到什么**（`GET /api/landmarks/{id}/poses`；地标页的"公开的拍摄位置"表和点云上的标记；风格化查看器在素模上画出来）：

- 每行有这些字段：
  - 公开 id：用部署密钥算的 12 位，不是库内 id；
  - 来源；
  - 位置：取整到 1 米，坐标是地标 ENU；
  - 朝向、俯仰、横滚：取整到 1°；
  - 水平视角：取整到 1°（D33；D30 时是 5°）；
  - 宽高比；
  - 2σ 范围：按取整放宽，再向上取整。

  每行没有上传者、时间、模型或扇区。D32 起，每一行的照片本身也能看（去掉元数据、缩小，见 [D32 的记录](D32-terms-compare-appearance.md)的照片接口）。
- 来源，按先后选：
  1. 模型重建（`sfm`）：坐标系定准了的已发布模型里、没被标记的相机；
  2. 与模型比对（`loc`）：视觉定位，现在关着（见下面）；
  3. 手机 GPS + 罗盘（`exif`）：只用标为真北的罗盘。这一行标"手机 GPS + 罗盘（未经模型核对）"，没有高度，画在地上，带这个来源实测落在范围里的比例。
- 列表是一张快照：只含最近一次重建作业结束前上传的照片。

**扣下不显示的**（宁可没有位姿，也不画粗糙的）：

- 只有 GPS、没有可用罗盘的照片；
- 罗盘是磁北或没标注的照片：这类罗盘常差 90° 左右；
- 坐标系没定准的模型里的相机：这种模型只有先验、没有吸附；
- 被标记的相机，例如离自己的 GPS 太远、和罗盘对不上；
- 定位关着时，以前存下的视觉定位结果。

基准把"扣下的位姿本来是对的"记成 `photo_pose_withheld_right`，这就是不显示粗糙位姿的代价：每次运行 dev 10.5 张、test 5 张。同时挡掉的错位姿是 dev 17.5 张、test 14.5 张。

**测出了什么**（指标第 8 版；commons-ten-v1 的 D31 全新运行在 716de16 上补算，两次重复的中位数，假定每张通过的照片都同意。完整的表在 [docs/BENCHMARK.md](../BENCHMARK.md) 6.12 节）：

| 现在的产品（定位关着） | dev（核心五栋） | test（留出五栋） |
|---|---|---|
| 通过的照片 | 460 | 399 |
| 显示位姿的（模型重建 / 手机 GPS + 罗盘） | 317（277 / 40） | 179.5（134 / 45.5） |
| 有参考位姿的里面：对 / 错（10 米 / 15°） | 142.5 / 78.5 | 62 / 34.5 |
| 落在自己 2σ 范围里 | 86% | 88% |
| 手机 GPS + 罗盘：有参考的里对的 | 5.5 / 10.5 | 1 / 14 |

- 显示的位姿约三分之一离参考超过 10 米或 15°。但 86–88% 落在它们自己标出的 2σ 范围里：范围是诚实的，只是宽。
- 手机 GPS + 罗盘的位姿在留出集上几乎都不准：14 张有参考的只有 1 张在 10 米 / 15° 内，82% 在范围里。
- 和 D31 的打分比，138 个张次变了，每个都有解释：
  - 69 个是磁北或没标注的罗盘不再显示；
  - 37 个是坐标系没定准的模型里的相机不再显示；
  - 32 个是取整以后判定跨过了对错的线。

  `photo_pose_*` 以外的指标一个都没变。
- 在一次真实全新运行的数据副本上读了所有不用登录的接口：没有库内 id、密钥、撤回凭证、GPS、上传时间或精确的相机位置。

**视觉定位：做了，默认关**（`crowd3d/localize.py`，`Settings.localize_photos`）。不在任何已发布模型里的同意照片，用 PnP 定位到地标已存的地图里（要有 EXIF 焦距）。是否打开由事先写好的标准 `eval/criteria/d30-v1.json` 决定。

- **结论：保持关闭。** 原因有两个：
  - 代价规则没过：定位要用掉运行 CPU 的 26.7%（dev）和 66.5%（test），上限是 25%。圣家堂一栋每次花约 1,300 CPU 秒，一张也没定位上。
    - 只有 test 这一条是稳的。分母是前一天 D31 运行的 CPU，分子是第二天测的；同样的工作，第二天要多用约 1.5 倍 CPU（洗礼堂定位关着的对照运行，每一步都一起慢），看来是机器慢了。按这个倍数换算，dev 约 17–19%，会过；test 约 41–46%，仍然不过。
  - `run` 还不给运行里的定位位姿打分，所以"显示的等于测的"这一条核对没过。
- 准确和隐私的守卫都过了：有参考位姿的定位位姿没有一张显示错，没有错面，没有泄漏。
- 打开的话能多出什么：每次运行约 860 张通过的照片里，多放准 9 张（约 1%），在勃兰登堡门、洗礼堂、比萨和印度门上。
  - 这 9 张里 4 张今天没有位姿，5 张今天只有手机 GPS + 罗盘的位姿（其中 2 张是错的）。
  - 能核对的 6 张全对。
- 证据很少。另一个更大的测试是"留一法"：160 张参考照片，先从地图里拿掉再定位。接受的 110 张里 24% 是错的，一半是定位器自己的错。
- 打开之前要做四件事：
  - 一个便宜得多的定位器，或者负责人明确决定接受这个代价（要写明是看过这些结果之后的决定）；
  - 再测代价时，定位的 CPU 和运行的 CPU 在同一台机器、同一段时间里测（或者带一个对照运行按倍数换算），并把对照写在结果旁边；
  - 基准给运行里的定位位姿打分；
  - 重复几次全新运行的开 / 关对比。原因是一次打开定位的运行里，模型的轮廓转角从 1.6° 变成了 10.2°，不知道是不是偶然。

**还等产品负责人答复的两个问题**（现在用的是默认答复）：

1. 只有手机 GPS + 罗盘的位姿要不要显示？
   - 默认：只显示罗盘标为真北的，标"手机 GPS + 罗盘（未经模型核对）"，附上这个来源实测落在范围里的比例（按来源分开、给最低和最高的一栋，不是一个合并的数）。磁北或没标注的不显示，只有 GPS 的从来不画。
   - 数据：上面说的，留出集 14 张里只有 1 张在 10 米 / 15° 内。D31 的运行里，有参考的磁北位姿 23 个张次，本来对的 4 个、错的 19 个，现在都不显示了。
   - 另两种选法：两种罗盘都显示，各带自己的范围；或者一张都不显示，只等模型重建或视觉定位放准。
2. 共同完成者的昵称和公开位置会不会对上号？
   - 默认：保留昵称、去掉每人的照片数，公开位置只在一次重建作业结束时更新，上传说明写明剩下的风险（D32 起用户协议也写明）。
   - 另一种选法：有公开位置的地标不显示昵称。
