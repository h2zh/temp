# Crowd3D 画风（主题）说明

> 2026-10-22。决定 D7 已由产品负责人拍板：画风由产品负责人定，所以把**测到的东西**和**长什么样**分开。本文写给美术和设计：怎么加一个画风、画风文件里每个字段的意思、哪些规则不能破（诚实约束）。代码在 `web/themes.js`、`web/themes/*.json`、`web/stylized.js`；整体设计见 `docs/STYLIZED_MODEL.md`（§3.7、§3.8、§4、§9.2）。

## 1. 原理：测到的和长什么样分开

- 风格化作业（`crowd3d/stylize.py`）只用一套封闭的颜色画立面：30 种调色板色（每种属于一个色族）、它们的描边暗色（调色板色 × 0.62）、墨色、素模的底色和斜纹色。
- GLB 自己说明每种颜色是什么：scene extras 的 `style.colors` 列出每种颜色的名字、RGB、角色（`palette`、`shade`、`ink`、`clay`、`clay-hatch`、`clay-roof`）和色族；平涂材质在自己的 extras 里写颜色名；立面贴图集是无损 PNG。
  - 无损要专门保证：原型原来用 PIL 的 `quantize()` 压成索引色 PNG，实测随机贴图集里约四分之一会把墨色 (45, 42, 50) 和一种暗色 (32, 37, 50) 合并。现在色板逐一按实际颜色构造，有测试覆盖。
- 所以查看器能按颜色精确查表，把贴图集一个纹素一个纹素换成画风里的颜色，**不用重跑风格化**。参考模型实测：洗礼堂的 32 万多个纹素全部精确命中颜色表，没有一个需要近似匹配。
- 每个立面纹素的来源（素模 / 实拍 / 底色补洞，见 STYLIZED_MODEL §3.3）存在一张同样布局的灰度图集里（scene extras 的 `texel_provenance`），审计用它检查发布出去的字节。
- 链接不带 `theme` 参数时就是默认画风。实拍部分的颜色、描边、光影和原来的查看器一样（原来逐像素对比两座参考建筑，最大差 1/255）；只有素模色往蓝调了一点（ΔE00 1.1–3.6，见第 3 节末尾和第 5 节），因为按查看器真实的光照算，原来的素模条在投影里离 snow 只有 5.2。查看器为此对默认画风也按颜色表换素模纹素。

## 2. 怎么加一个画风

1. 复制 `web/themes/storybook.json`，改名为 `<id>.json`。id 只用小写字母、数字和连字符，和文件名一致。
2. 按第 3 节改字段。
3. 打开 `stylized.html?model=<模型>&theme=<id>` 就能看，不用改代码。
4. 要出现在面板的"画风"下拉框里，把 id 加进 `web/themes/index.json`。测试会检查目录里每个画风文件都列进去了。
5. 跑 `node --test 'web/tests/*.test.mjs'`：校验器（第 4 节）逐个检查 `web/themes` 里的画风。没通过校验的画风，查看器也会拒绝：退回默认画风，并在面板上写明原因。

## 3. 字段

颜色一律写成 `#rrggbb`，意思是"看到的颜色"（sRGB，打光之前）。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 和文件名一致 |
| `schema` | 是 | 现在是 `1` |
| `name` | 是 | 中文短名，显示在下拉框里（建议 ≤ 6 个字） |
| `description` | 是 | 一行中文，说清是什么画风 |
| `palette.rules` | 是 | 调色板规则列表，按顺序作用在匹配的颜色上，见下文 |
| `palette.colors` | 否 | `{调色板颜色名: 颜色}`，直接指定，优先级最高 |
| `shade` | 否 | 贴花描边暗色。`{"factor": 0.62}`：映射后的颜色 × factor（默认 0.62）；或 `{"color": "#…"}`：所有描边暗色用同一个颜色 |
| `ink` | 是 | 墨色：门窗的框线 |
| `clay.wall` | 是 | 素模底色（立面贴图里没拍到的部分，以及整面素模墙） |
| `clay.hatch` | 是 | 素模斜纹色（立面贴图里） |
| `clay.face` | 否 | 没有贴图的整面素模墙和转角，默认等于 `clay.wall` |
| `clay.roof` | 否 | 没拍到的屋顶，默认是 `clay.face` 稍暗一点（线性光 × 0.93） |
| `clay.hatch_shade` | 否 | 整面素模（没有贴图的墙、转角和没拍到的屋顶）上斜纹的明暗：底色 × 这个数（线性光），0.5–0.92，默认 0.84。屋顶的斜纹色因此是 `clay.roof` × 这个数 |
| `outline` | 是 | `null` 表示不要描边；否则 `{"color", "width_px", "silhouette_color"?, "crease_color"?, "crease_width_px"?}`：剪影宽 `width_px`（CSS 像素），折痕线默认是它的 0.7 倍（至少 1 px），两者颜色默认都是 `color`。地址里的 `outline=<px>` 会覆盖宽度 |
| `toon.steps` | 是 | 卡通明暗的档位，2–6 个递增的亮度，最后一个必须是 1 |
| `lights.hemisphere` | 是 | `{"sky", "ground", "intensity"}` 半球光 |
| `lights.sun` | 是 | `{"color", "intensity"}` 主光 |
| `background` | 是 | `{"type": "solid", "color"}` 或 `{"type": "gradient", "stops": [{"color", "at"}, …]}`（自上而下，`at` 从 0 到 1） |
| `ground` | 是 | `{"color", "rim"}` 地面圆盘和它的边 |
| `locked_frame` | 否 | 待解锁墙上虚线框的颜色 |
| `gradient` | 否 | `null`，或 `{"top", "bottom", "strength"}`：楼身从下到上乘一层渐变色调（低多边形渐变的效果），`strength` 0–1 |

**调色板规则**：每条规则是 `{"match", "ramp"?, "hue"?, "saturation"?, "lightness"?, "mix"?}`。

- `match`：`"*"`（全部）、色族名、调色板颜色名，或它们的列表。
- 一条规则里的操作按这个顺序做：
  1. `ramp`：2–8 个颜色组成的渐变，按原色的明度 L\*（0–100）在渐变上取色，相当于渐变映射；
  2. `hue`：色相转多少度；
  3. `saturation`：饱和度乘多少（HSL）；
  4. `lightness`：亮度加多少（HSL，百分点）；
  5. `mix`：`{"color", "amount"}`，和某个颜色按比例混合。
- 一个颜色会依次经过所有匹配它的规则，最后再看 `palette.colors` 有没有直接指定。

**色族和调色板颜色名**（和 `web/themes/palette.json` 一致，那是 `crowd3d.stylize.color_table()` 的副本，有测试保证两者相同）：

| 色族 | 颜色名 |
|---|---|
| `neutral` | snow、stone-light、stone、pebble、stone-dark、graphite、charcoal |
| `sand` | cream、sand、ochre |
| `gold` | sunflower、gold |
| `brick` | peach、terracotta、brick、rust |
| `green` | mint、leaf、forest、pine |
| `blue` | sky、lake、navy |
| `slate` | slate-light、slate、night |
| `wood` | wood、cocoa |
| `copper` | copper、teal |

**默认画风的一个历史包袱**：原来的查看器把素模色多做了一次颜色空间转换，所以没有贴图的整面素模墙比贴图里的素模条暗一档；剪影线也显示成 #070608，而折痕线是墨色 #2d2a32。`default.json` 保留了这种"整面素模暗一档"的关系和剪影色。新画风可以不写 `clay.face`，整面素模和贴图里的素模就是同一个颜色。要不要把默认画风也统一，由美术决定。

**默认画风的素模色改过一次**（校验器改成按查看器真实的光照算之后，原来的值在投影里过不了第 4 节的门槛）。按"改动最小、留 0.5 余量"选的新值，都只是往蓝调了一点：

| 字段 | 原来 | 现在 | 两者差 ΔE00 |
|---|---|---|---|
| `clay.wall`（贴图里的素模条） | #e4e8ee | #dbe6f3 | 3.6 |
| `clay.hatch` | #d0d7e2 | #d0d7e6 | 1.8 |
| `clay.face`（整面素模墙） | #c6ceda | #c8d1df | 1.1 |
| `clay.roof` | #c0c7d3 | #c9d2e2 | 3.1 |

GLB 里的素模纹素仍是风格化作业写的 #e4e8ee / #d0d7e2（颜色表里的 `clay`、`clay-hatch`），查看器按颜色表换成上面的值，和别的画风换色走同一条路。

## 4. 诚实约束（校验器 `validateTheme`）

画风只能"换衣服"，不能让素模看起来像有人拍过。

1. **素模不能像实拍**：每个素模色（`clay.wall`、`clay.hatch`、`clay.face`、`clay.roof`，以及查看器在整面素模上画的斜纹色：墙上是 `clay.face` × `hatch_shade`，屋顶上是 `clay.roof` × `hatch_shade`），到这个画风下实拍立面可能出现的每个颜色（映射后的 30 种调色板色、它们的描边暗色、墨色），CIEDE2000 色差都要 ≥ **7.5**。底色补洞用的是该墙映射后的底色，也在这个集合里。
   - 这个比较按设定的颜色做一遍，再在查看器实际渲染的每种光照下各做一遍（`lightConditions()`，和 `web/stylized.js` 用的 three.js r160 卡通材质同一个算法）：一个面受的光 =（半球光 + 主光 × 明暗档）÷ π，再乘渐变色调；素模和彩色面都乘上同一个光，按帧缓冲那样在 1 处截断，再比色差。具体取样：
     - **半球光的天空色和地面色都算**：竖直的墙一半天空一半地面，平屋顶只有天空，陡的斜屋顶（法线朝上分量 0.5）在中间；
     - **主光乘每一档明暗**（面朝哪边决定落在哪一档，所以每档都算），再加上**投影里**（被别的体块挡住：只有半球光）；
     - **按绝对亮度算**，不先归一化：光太强时浅色会一起截成白色，太弱时颜色会挤到一起，两种都会被拒绝；
     - 有渐变时，在渐变底部、中部、顶部各算一遍。
   - 光照对素模和彩色面一视同仁地乘上去，但会改变两者的色差。例子（测试里都有）：把 `dusk` 的光换成蓝色，按设定颜色素模离奶油色很远，蓝光下素模斜纹色和奶油色只差 1.9；把 `storybook` 的半球光地面色换成绿色 #00e000，投影里的墙上整面素模的斜纹和 stone 只差 3.7；把它的光调到半球 4、主光 5，浅色墙一起截成白色，差 0。校验器都会拒绝。
2. **斜纹要看得见**：在上面每种光照下，`clay.hatch` 和 `clay.wall`、整面素模墙上的斜纹和 `clay.face`、屋顶上的斜纹和 `clay.roof`，ΔE00 都要 ≥ 3（所以 `hatch_shade` ≤ 0.92；暗的画风在投影里还要更低，`dusk` 用 0.78）。屋顶近于纯黑（例如 #0a0a0a）时斜纹差不到 0.2，会被拒绝。
3. **每个调色板颜色都要有着落**：有规则匹配到它，或者在 `palette.colors` 里写了。
4. **格式**：字段类型和范围；不认识的字段（多半是打错字）直接报错，不会悄悄用默认值；`name` 和 `description` 是一行中文。

为什么门槛是 7.5 而不是 10：默认画风的素模条 #dbe6f3 在它最暗的光照下（墙在投影里）离 snow 只有 ΔE00 8.0（原来的 #e4e8ee 按设定颜色是 7.9，投影里只有 5.2，所以改了色，见第 3 节）。STYLIZED_MODEL §4.2 计划换一个离所有色族都 ≥ 10 的素模色，换完以后把 `MIN_CLAY_DELTA_E` 提到 10。

画风改不了的东西：形状、哪里有颜色、哪里是素模、底色补洞补在哪、来源卡片、待解锁牌子。这些都来自 GLB，画风只决定它们用什么颜色、什么光影画出来。

## 7. 限制

- 画风只换颜色和光影，不换形状语言：圆角、贴花的形状、描边画在哪，都由风格化作业决定。要换形状语言，得改 `crowd3d/stylize.py` 并重跑。
- 校验按取样算光照（第 4 节）：墙、陡斜屋顶、平屋顶三种朝向，投影里和每一档明暗，渐变的底、中、顶。取样点之间的情况不单独算：阴影的软边（主光只挡掉一部分）、别的屋顶坡度、渐变的其他高度。比较的是同一种光照下的素模和彩色面；亮档的素模和暗档的实拍面放在一起比，不在校验范围内。
- 远看时贴图过滤会把斜纹和底色混成一个平均色，这个平均色不单独校验。四个参考画风实测：平均色到实拍色最近 7.8（绘本粉彩，整面素模墙在投影里对 peach），默认 7.9，黄昏 8.7，蓝图 14.1。
- 修订之前写的 GLB 没有颜色表：查看器改用 `web/themes/palette.json`。那批贴图集用的是不精确的量化，查表时先找最近的表内颜色兜底：R、G、B 三个通道差的绝对值**加起来** ≤ 6 才算匹配（不是每个通道各差 6 以内），还匹配不上的纹素保持原样（计数在 `window.__stylized.theme.texels.unknown`）。例如旧图集里的 (39, 39, 50) 离墨色 (45, 42, 50) 是 6 + 3 + 0 = 9，离 night.shade (32, 37, 50) 也是 9，所以保持原样，在把墨色换掉的画风（如 `blueprint`）里这些纹素还是原来的深色。重跑风格化后就没有这个问题。
- 下拉框只列 `index.json` 里的画风；没列进去的画风用地址参数 `theme=<id>` 也能打开。
